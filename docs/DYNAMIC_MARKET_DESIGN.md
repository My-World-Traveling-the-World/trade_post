# 动态市场与供需模型设计（Dynamic Market & Supply/Demand Model）

> 状态：设计草案 v2（已全量采纳 DYNAMIC_MARKET_REVIEW.md 评审意见）
> 适用：tradepost 集市 mod 价格机制重构
> 关联：SYSTEM_REPORT.md（现役机制）、OPTIMIZATION_REPORT.md（现役性能/缺陷）、DYNAMIC_MARKET_REVIEW.md（评审，本版修订依据）

## 摘要

把价格机制从「手写乘区堆叠」重构为「供需账本驱动的动态市场」：

    当日牌价 P = 内在价值 × 供需锚(慢) × 情绪噪声(小)
    买价 = P；卖价 = P × (1 − fee)
    库存只限制数量、不参与定价

一次重构同时解决三个现存痛点（0.75 死板、乘区死板/贵货乱跳、缺真实供需），并用「买卖同锚 + fee 单向」保证**原地/隔日不可套利**。

> ⚠️ 评审发现的现役漏洞（与本文案正交，可立即修）：diamond_block / netherite_block / lapis_block / redstone_block 四个方块**不在** values.json 手写表，会落到 tag_values.json 的 "#c:storage_blocks": 8.0，而钻石基价 values.json:78 = 24。后果：钻石块约 8×稀有度≈19 就能买到，拆成 9 颗钻石再卖 ≈ **8 倍套利**。修法见 §7。

## 1. 背景：三个现存痛点

| # | 痛点 | 现状 | 根因 |
|---|---|---|---|
| A | 卖价被 0.75 钉死 | 卖出价 ≤ 本村要价 × 0.75（LOCAL_SPREAD），玩家普遍感觉被宰 | 无真实供需，只能用固定价差硬防「原地倒卖」 |
| B | 贵货乱跳、便宜货不动 | 下界合金(180)单日噪声 ±40 颗，小麦(0.03)永远纹丝不动 | 全是乘性因子，绝对波动 ∝ 基础价，被 6000 倍价差放大 |
| C | 价格是写死的 | worldIndex / area / stock 都是闭式曲线，不反映真实成交 | 缺供需数据，只能拍脑袋 |

> 防倒卖 exploit 的历史：早期封顶靠买页货架价，货被买空后整行消失、封顶失效，玩家「买光→再卖」稳赚约 2 倍并可反复套空银库。现由 askUnit（VillageMarket.java:644，注释 634-643）修复，但代价是全局 0.75 价差。本文案的目标之一就是从结构上消灭这个 exploit，而不靠 0.75。

## 2. 目标与非目标

**目标**
1. 建立动态整体市场：价格随时间、随真实供需变化。
2. 引入显式供需数据（账本），可查、可调试、可调。
3. 从结构上杜绝无风险套利（原地倒卖 / 隔日扫货）。
4. 价格稳定：有锚、有界、可预测上限。
5. 性能：服务端主线程零聚合，成交只记账 + 日结快照。

**非目标**
- 不重做基础价表（values.json 的 0.03~180 跨度另议）。
- 不引入玩家间交易所/拍卖行（本期不涉及）。
- 不改配方、掉落、合成成本（但配方**关系**要进定价，见 §7）。

## 3. 核心思想（一句话）

> 价格 = 内在价值 × 供需锚（慢）× 情绪噪声（小）；买卖同价、卖价打折；库存只限量、不定价。

## 4. 模型总览

                       ┌─────────── 每日离线结算 ───────────┐
                       │  账本 EMA → 锚更新 → 快照表(村×物品) │
                       │                                    │
     [供需账本 Ledger] ──► [供需锚 Anchor] ──► [牌价 P] ──► 买=P / 卖=P×(1−fee)
     S(供给) D(需求)        (慢变量,有界)         │                │
     三层: 全球/区域/本村                          └── [噪声 noise] ──┘
                                               (对数空间,当天固定)

     [库存 Stock] ──► 只限制「能买多少/能卖多少」，不进入价格

## 5. 部件与公式（含理由）

### 5.1 供需账本 Ledger（数据层）

每件货 × 每层（本村/区域/全球）维护两条日流量：

    S = 供给：物品「进入」经济 —— 玩家卖、挖矿/农场产出、NPC 卖
    D = 需求：物品「离开」经济 —— 玩家买、合成消耗、NPC 买

    每日结算（EMA，α=0.2，半衰期≈3天）：
    S ← S + α×(今日S − S)
    D ← D + α×(今日D − D)

**为什么这样好**
- 只在成交时写账本、每天离线结算一次，不在 tick 里聚合（服务端主线程零压力）。
- EMA 有界、平滑、天然与现役 settle() 同日节奏。
- 首次让「供需」成为可查、可调、可做调试面板可视化的真实数据。

### 5.2 供需锚 Anchor（慢变量，价格心脏）

    netFlow  = D − S                          // 供不应求为正
    cap      = 村库存上限（沿用 Stock.java:24，仅作量纲参考）
    pressure = tanh( netFlow / (κ0 × cap) )   // 饱和压力，κ0 = 0.25

    a* = clamp( 1 + β × pressure, lo, hi )    // 目标锚：压力映射到倍数
    a  ←  a + η × (a* − a)                    // 一阶滞后逼近，η = 0.05
    a  ←  clamp(a, lo, hi)                    // lo = 0.5，hi = 3.0

    P  = base × a × noise

默认 κ0 = 0.25、β = 1.0、η = 0.05、anchor 区间 [0.5, 3.0]。

**为什么这样好**
- **饱和压力 tanh**：netFlow 大到 cap 的几倍后，压力不再线性增长（→±1）。既防止单笔鲸鱼单把压力顶穿，也解决旧版 pressure = netFlow/(volume+floor) 在薄市场「卖 10 件就 ≈ −0.91」的恒饱和问题。
- **目标映射 + 一阶滞后**：a* 先 clamp 进 [lo, hi]，不存在「持续短缺顶到硬边界卡死、持续过剩只降到 0.5」的上下不对称。单日最大涨幅 = η × β = 5%，与 fee 直接可比。
- **ηβ = 单日最大可预期涨幅**：这是 §6 防套利不变量的唯一自由参数；定死 η、β 后，fee 必须 ≥ ηβ。
- 旧版「anchor × (1+clamp(κ×pressure)) + λ(1−anchor)」被证明有致命稳态错误（精确递推不动点 = 20 被硬夹，一阶近似上下失效，评审 P0-1），整段删除，不再使用 λ 均值回归。

### 5.3 库存 Stock：只限量、不定价（最关键决策）

    库存 cap / regen / 过剩回收 保留原机制
    但库存不再乘进价格 —— 删除 buyImpact / sellImpact 这对不对称乘区
    （现役：buyImpact = clamp(1−0.85(r−0.5), 0.55, 1.45)  @Stock.java:57
           sellImpact = clamp(1−0.65(r−0.5), 0.68, 1.33)  @Stock.java:67）
    库存只回答：能不能买到（stock>0）、能买多少、能卖多少（stock<cap）。

**为什么这样好**
- 现役 exploit 的根源是「库存既限量又定价，且买卖两端按不同库存各算各的」。
- 把库存从价格里拿出后，「买光→要价飙→卖价飙」的通道从结构上消失，不再需要 0.75 硬压。

### 5.4 当日牌价 + 单向手续费 + 日内摩擦（取代 0.75）

    P(id, 村, 天) = base × anchor × noise
    买价 = P
    卖价 = P × (1 − fee)        // fee = 6%（首版建议 8%）

    日结后生成快照表：村 × 物品 → { 报价 P, 可买件数, 可卖件数 }
    开页只查快照表，不再实时生成货架（评审 P1-5：现役开页 2.4s 是货架生成成本）。

- 当天价格固定；成交只改账本与库存，不改当天 P。
- **日内摩擦（评审 P1-2）**：仅「当天固定」不够——买光全村价当天不动，日内零摩擦。二选一：
  - (a) 日内阶梯：当天内每成交一笔，P 抬/压 2%/档，总幅度 < fee，次日随快照重置；
  - (b) 滑点：单笔成交价在 [0.9, 1.1]×P 区间随成交量滑动，上限 < fee。
  推荐 (a)：实现简单、上限明确。

**为什么这样好**
- **当天不随成交变** → 原地「买→卖」必亏 fee，无瞬时套利。
- **日内阶梯/滑点** → 连「日内扫货再卖」也没有零风险窗口。
- **6% 替代 0.75（隐含 25% 价差）** → 玩家卖货不再被宰。
- **买卖锚同一个 P** → 需求差（anchor）同时体现在买卖两端，甩掉「卖价乘区是死的」问题。

### 5.5 情绪噪声 noise（对数空间，相对波动）

    噪声在「对数空间」施加：
    P = base × a × exp(noise)
    noise ~ U(−σ, +σ)，σ = 2.5%，当天/当村固定、次日重掷（对称零均值）

**为什么这样好（对照痛点 B）**
- **对数空间是相对波动**：所有物品都 ±2.5%，不分贵贱。旧版 m = 0.02 + 0.05×√base 是「绝对颗数」，把痛点 B 做反了（便宜货 ±96%、贵货 ±0.38%）。
- **便宜货的「会动」由 Lot 件数体现**：定价按件（unit），但交易按整数件，便宜货成交件数天然大，实际金额波动由件数放大——不需要在噪声里加绝对项。

### 5.6 三层合成（整体市场）

    anchor_combined = 1 + 0.15×d_全球 + 0.35×d_区域 + 0.5×d_本村
    （d = 各层 anchor − 1）
    各层一阶滞后速率 η 分级：η_全球 = 0.01  <  η_区域 = 0.03  <  η_本村 = 0.08

**为什么这样好**
- 本村反应最快（玩家直接感知）、区域次之、全球最慢，对应「快/中/慢」三层真实节奏；旧版三层共用同一个 λ，失去分层意义。
- 现役已有三层雏形（worldIndex / area / stock），只是写死曲线；账本化后变成真实驱动的慢/中/快三层。
- 跑商赚的是三层价差，而非原地倒卖。

### 5.7 每日收购预算 Budget（补 §5.3 缺的那道闸）

    每村每天一个收购预算 B（单位：颗绿宝石），所有收购行共用一个池子：
    B = clamp(β_w × wallet, 最贵单件卖价, wallet / 3)
    β_w = 0.1          // 银库 500 → 50 颗；银库 2000 → 200 颗
    成交时先扣 B，扣完的行标 ❌（复用售罄标记，不删行）
    只管「单价 ≥ 20 颗」的行：小麦/杂货/书这类便宜货只受库存与银库约束
    只记「单笔 ≥ 20 颗」的成交：一把一把卖便宜货不该把贵货的额度吃光

**为什么需要它**

深度 D 只按「件数」限量，而「件数 × 单价」才是钱。取 D = 90.5/√base（一个令铁锭 D=64 的标定），单村每天单物品最多能换走：

    V_max = D × (1−fee) × base = 83.3 × √base

| 货 | base | D（件/天） | 单件卖价 | V_max（颗/天） |
|---|---|---|---|---|
| 小麦 | 0.12 | 261 | 0.11 | 29.5 |
| 面包 | 0.22 | 193 | 0.21 | 39.9 |
| 铁锭 | 2 | 64 | 1.88 | 120.3 |
| 钻石 | 24 | 18 | 22.56 | 416.8 |
| 下界合金锭 | 180 | 7 | 169.20 | 1141.3 |

V_max 正比于 √base ⇒ 最贵与最便宜相差 √(180/0.12) = **38.7×**。这就是「单趟差距」的真实来源：不是配方成本，是「件数限额 × 单价」的比例失配。

预算把 V_max 夹到 min(V_max, B)；B 低于单件卖价时保底 1 件（否则贵货一件都卖不出，体验断裂）：

**表 A：银库 500**

|---|---|---|---|---|---|---|---|
| 0.1 | 50 | 29.5 颗 / 261 件 | 39.9 / 192 | 50.0 / 26 | 50.0 / 2 | 169.2 / 1（保底） | 5.7× |
| 0.2 | 100 | 29.5 / 261 | 39.9 / 192 | 100.0 / 53 | 100.0 / 4 | 169.2 / 1 | 5.7× |
| 0.3 | 150 | 29.5 / 261 | 39.9 / 192 | 120.3 / 63 | 150.0 / 6 | 169.2 / 1 | 5.7× |

**表 B：银库 2000**

| β_w | B | 小麦 | 面包 | 铁锭 | 钻石 | 下界合金锭 | 最大/最小 |
|---|---|---|---|---|---|---|---|
| 0.1 | 200 | 29.5 / 261 | 39.9 / 192 | 120.3 / 63 | 200.0 / 8 | 200.0 / 1 | 6.8× |
| 0.2 | 400 | 29.5 / 261 | 39.9 / 192 | 120.3 / 63 | 400.0 / 17 | 400.0 / 2 | 13.6× |
| 0.3 | 600 | 29.5 / 261 | 39.9 / 192 | 120.3 / 63 | 416.8 / 18 | 600.0 / 3 | 20.3× |

读法：β_w 越小差距越小，但到 5.7× 就压不动了。

> ⚠️ 阈值是必需的，不是偷懒：2026-11-13 实测，β_w=0.1、银库 2009 的村，玩家卖掉 3 块下界合金（100+94+89 = 283 颗）之后，`avail` 对**每一行**都算成 0 —— 连 1 颗的书、2 颗的羊毛都画 ❌，玩家的反馈是「什么都不能卖了」。预算必须只作用于贵货行，且只统计大额成交。

**收敛极限（数学事实，别指望 1.5×）**

只要「最贵单件卖价 169.2」＞「最便宜货的日总额 29.5」，差距就不可能低于 169.2/29.5 = 5.7×。要再往下只有两条：

1. **压缩 base 跨度**（§11-5 的幂压缩）：下界合金 180 → 88 时单件卖价 82.7 颗 ⇒ 差距 ≈ 2.8×。代价是配方成本是线性相加的，部分配方会亏本。
2. **提高便宜货日总额**：把 D 的指数从 −0.5 收到 −0.75（V_max 正比于 base^0.25，差距 6.2×），但地板仍由单件价决定，收益有限且要重标定全部 D。

所以本设计的合理目标：**单趟差距 38.7× → 5.7~6.8×**，而不是抹平。

**顺带修正一个口径错位**：现役「单趟 38.7×」与「每小时收入 2.4×」并不一致——这个错位本身就是「背一包贵货一趟赚翻」的来源。新模型把两个口径对齐到同一量级（~6×），玩家感受从「专挑贵的背」变成「卖什么都得跑量、跑村」。

**与 §6 的关系**：预算只限「能卖多少」，不改单价 ⇒ §6 三条不变量一条不动；它额外给「持有 N 天」加了一条明牌上限（每天 ≤ B）。

**标定与自洽**

- 必须 ≤ wallet / 3：现役银库日回补 3%（walletRegen 0.03），B 取 0.1×wallet 时收支大致平衡，村子不会被卖穿。
- 与库存回补一致：B 花完行仍显示 ❌，次日随快照重置。
- 先到先得（按成交顺序扣），不做排队、不做预留。

**UI**：卖页顶部一行「今日收购额度还剩 N 颗」；额度不足一件的最贵货，行内标「今日额度不够」，而不是让整行消失。

**验收（phase 2）**

1. 送 2304 件小麦进村：只成交 261 件，其余变 ❌。
2. 送 2 块下界合金：B=100 时只成交 1 块，第 2 块 ❌；B=400 时两块都成交。
3. 连续模拟 30 天只卖不买：银库不低于初值 80%。

## 6. 核心不变量（防套利口径）

> **原地 / 隔日不可套利；持有 N 天是「投资玩法」，收益有明牌上限。**

- **原地**：买 = P、卖 = P×(1−fee)，必亏 fee。
- **隔日**：单日最大可预期涨幅 = ηβ = 5% < fee（6%，首版 8%），「今天买、明天卖」最差也是亏 1~3%。
- **持有 N 天**：累计最大可预期涨幅 = ηβ × N，这是明牌上限，不是漏洞——玩家赌对方向赚的是「承担价格风险」的钱，属投资玩法；我们只保证「无风险」套利不存在。
- **推论（评审 P0-2，阶段 2 前置条件）**：任何「提前可预测、且买卖幅度不同」的日期乘区（如现役 marketDaySell = 1.35 / marketDayBuy = 1.10）都是无风险套利源，必须对称化（买卖同倍，建议都取 1.10）或并入 anchor。不是可选项。

**chainFactor（评审 P0-3，上一版整节缺失）**
现役 Chain.factor（market/Chain.java:68）用 levelFactor 递归算「本村成本 / 中立成本」，clamp [0.6, 2.0]；本设计删掉 levelFactor（demandBonus/roleDemand/supplyPenalty）后，chainFactor 的递归根基就断了，必须补交代，否则「原料贵、成品不跟着贵」会打开跨物品套利。两条修法：
1. **anchor 沿配方图传播**：成品 anchor 由原料 anchor 加权合成（或成品 P 直接由「原料 P 之和 × craftPenalty」算出，再乘成品自身稀缺因子），让「原料贵 → 成品也贵」由数据保证，而不是靠写死系数。
2. **可分解物强制对称**：块价 = n × 原料价，不吃 craftPenalty。否则「买块 → 拆 n 件 → 卖」套利系数 = fee/craftPenalty：现役 0.75/0.65 = 1.154（+15%），新案 0.94/0.65 = 1.446（+45%）。

> ⚠️ 现役价表洞（评审 P0-3，已核验，与重设计无关、可立即修）：values.json 手写表有 iron_block 18.0(=9×2) / gold_block 28.8(=9×3.2) / coal_block 3.2（values.json:73-75），但 diamond_block / netherite_block / lapis_block / redstone_block 四块**缺失**，落 tag_values.json:17 的 "#c:storage_blocks": 8.0。钻石块约 8×稀有度≈19，买一块拆 9 颗钻石（values.json:78 = 24）再卖 ≈ **8 倍套利**。修复：把这 4 块补进手写表，取 n × 原料价（不吃 craftPenalty），立即生效。

## 8. 参数默认值与标定方法

| 参数 | 默认 | 含义 | 标定 |
|---|---|---|---|
| fee | 6%（首版 8%） | 卖出折扣 | 必须 ≥ ηβ=5%；首版留 3% 安全垫 |
| η | 0.05 | 本村锚滞后速率 | 与 β 共同决定单日最大涨幅 ηβ |
| β | 1.0 | 压力→倍数映射强度 | 固定 1.0，先调 η |
| κ0 | 0.25 | 压力饱和尺度（×cap） | 调至「真实短缺 5~10 天把价格推满」 |
| anchor 区间 | [0.5, 3.0] | 锚硬边界 | 下限 0.5 绝不归零、上限 3.0 |
| α | 0.2 | 账本 EMA | 半衰期≈3 天 |
| η 分级 | 0.01 / 0.03 / 0.08 | 全球/区域/本村 | 快慢分层 |
| 噪声 σ | 2.5% | 对数空间相对波动 | 所有物品同幅 |
| marketDaySell | 1.10 | 与 buy 对称 | 阶段 2 前置，防同日套利 |
| 三层权重 | 0.15/0.35/0.5 | 全球/区域/本村 | 先固定本村 0.5 |
| 日内摩擦 | 2%/档 | 日内阶梯幅度 | < fee |
| 预算系数 β_w | 0.1 | 每日收购预算 = β_w × 银库 | 从 0.1 起；差距 6.8× 可接受，调小只会让贵货更早 ❌ |
| 预算上限 | 银库/3 | 防「卖穿村子」 | 与 walletRegen 0.03 自洽 |
| 预算保底 | 1 件 | B < 单件卖价时仍可卖 1 件 | 否则 169 颗的下界合金在小村永远卖不出 |

## 9. 跑商示例（铁锭 base=2）

| | 产铁村 A | 缺铁村 B |
|---|---|---|
| 全球缺铁 | 1.00 | 1.00 |
| 区域 | 0.88（过剩） | 1.12（短缺） |
| 本村账本 | 0.90 | 1.15 |
| 合成 anchor | 0.91 | 1.12 |
| 牌价 P | 1.82 | 2.24 |
| 卖价（×0.94） | — | 2.10 |

A 村买 1.82 → 运到 B 村卖 2.10，毛利 ≈15%/件；运输成本与风险是玩家付出的「劳动」。

> 注意：15% 毛利依赖区域 0.88/1.12 与本村 0.90/1.15 两层同时拉开。若真实数据拉不开、毛利跌到 fee(6%) 以下，跨村跑商就不成立——回 §11 标定区域/本村权重。**原地倒卖必亏 6%** 这一点始终成立。

## 10. 分阶段落地里程碑

0. **phase 0 修三个 P0（阻塞项，先于记账）**：① anchor 改「目标映射 + 一阶滞后」（P0-1）；② marketDaySell 改 1.10（P0-2）；③ 补 chainFactor/配方关系交代 + 4 个方块手写价（P0-3）。
1. **phase 1 只记账、不改价**：接入 S/D 账本 + 日结快照表，出调试面板可视化真实供需。观察数据形态 1~2 周。
2. **phase 2 替换单村定价**：本村层 anchor + 牌价 + fee，删 buyImpact/sellImpact；加每日收购预算 B（§5.7，β_w=0.1）；保留 min(卖价,要价×0.75) 兜底开关，稳定后撤。
3. **phase 3 开放区域层**：区域账本 + anchor，产生跨村价差 → 跑商玩法。
4. **phase 4 开放全球层**：全球账本 + anchor，长周期趋势。
5. **phase 5 噪声与事件**：对数噪声 σ=2.5% + 日内摩擦 + marketDay 对称化收尾。

每阶段独立可回滚；未验证上一阶段稳定前不开下一阶段。
