**总体判断：方向正确，可以按阶段推进；但当前参数直接落地会在 30 天内重开三类套利，其中一类是同一天内的白送。**

## 1. 值得保留的设计（这些别改）

1. **买卖同一个 P，卖价 = P×(1−fee)**。现役卖价公式那一长串需求系数（1.35/1.18/1.00/0.90）在库存 50% 时全部被封顶吃掉（见 SYSTEM_REPORT §4.2：算出来 3.186，成交 1.275），本质是装饰。单一 P 让"需求"真正同时体现在买卖两端，这是全篇最有结构性价值的一条。
2. **库存退出定价，只限量**。现役 `Stock.buyImpact`（0.55~1.45）与 `sellImpact`（0.68~1.33）两端不对称，且按物品独立计算，这正是"买光→再卖"的机制成因。删掉它们是从结构上消灭这类套利，比再加一个 `askUnit` 式的补丁更对。
3. **账本作为一等数据**。现役 `worldIndex`/`area`/`stock` 都是闭式曲线，玩家看不到"为什么贵"。账本让价格可解释、可调试、可做面板，这是把机制变成玩法的前提。
4. **不变量式表述**（fee ≥ 单日可预期涨幅）。比"拍一个 0.75"高一个层次，且 §6 那条推论（确定性日期乘区本身就是套利源）是真见识 —— 现役的 `marketDaySell 1.35 / marketDayBuy 1.10` 恰好就是这种乘区。
5. **分阶段可回滚**。尤其"只记账、不改价"这一阶段，是这类重构最省事的验证方式。

## 2. 阻塞级问题（P0）

### P0-1　anchor 的稳态不是 2.0，是 20

设计 §5.2 的递推：

```
anchor ← anchor × (1 + clamp(κ×pressure, −0.05, +0.05))
anchor ← anchor + 0.05 × (1 − anchor)
anchor ← clamp(anchor, 0.2, 5.0)
```

代入 pressure 取上限（κ×p 被夹到 0.05）：

```
a' = a×1.05 + 0.05×(1 − 1.05a) = 0.9975·a + 0.05
不动点：a = 0.05 / 0.0025 = 20
```

代入 pressure 取负上限：

```
a' = 0.95a + 0.05×(1 − 0.95a) = 0.9025·a + 0.05
不动点：a = 0.05 / 0.0975 = 0.513
```

所以：

- **持续短缺**：anchor 每天 +0.0025×(20−a)，起点 1 时 +4.75%/天，约 **94 天**顶到硬上限 5.0，然后一直卡在 5.0（因为 a=5 时每天仍 +0.0375）。
- **持续过剩**：收敛到 **0.513**，永远碰不到文档说的 0.2 下限。

文档写的 `1 + pMax/λ = 2.0` 是一阶近似，在这里恰好失效（λ = 0.05 与 κ·pMax = 0.05 同阶，二阶项不可忽略）。后果不是"数字不好看"，而是：**任何长期缺货的村子会把价格顶到 5 倍并永久停留**，而长期过剩的村子只降到 0.51 —— 上下严重不对称。

**修法（建议直接替换 §5.2）**：用"目标值映射 + 一阶滞后"，两个参数分别对应手感与上限，不用试：

```
a* = clamp(1 + β × pressure, lo, hi)        // β：供需把价格推多远
a  ← a + η × (a* − a)                       // η：多快到位
单日最大涨幅 = η × β                         // 可精确设成 0.05，与 fee 配平
```

取 η=0.05、β=1.0：单日最大 +5%、稳态区间 0~2.0（pressure=±1 时 0 与 2.0）。
取 η=0.10、β=0.5：单日最大 +5%、稳态 0.5~1.5（更温和，适合首版）。
稳态由 `a*` 决定，天然有界；不再需要"积分 + 漏桶"的调参博弈。

### P0-2　fee 6% 之前，marketDay 必须先对称化

§7 把 `marketDaySell 1.35 / marketDayBuy 1.10` 标成"对称化或并入 anchor"，但排在最后。而 §6 的不变量只覆盖 pMax = 5%，**没有覆盖这个 35%**：

| 操作 | 计算 | 结果 |
|---|---|---|
| 集市日同村同日：买 → 卖 | 买 1.10P，卖 1.35P×0.94 = 1.269P | **+15.4%，一个 tick，可无限循环** |
| 非集市日买入、等 6 天后的集市日卖 | 买 1.00P，卖 1.269P | **+26.9%** |

集市日是按（村、种子、天数）确定性算的（`marketDayPeriod = 6`），玩家可提前知道。只要 0.75 一撤、fee 只有 6%，这就是印钞机。

**修法**：把 `marketDaySell` 改成 1.10（与买侧同倍），或改为"只作用于买侧"（集市日货多但不多给钱），或把它折算进 anchor 而不做独立乘区。**这是阶段 2 的前置条件，不是后续优化项。**

### P0-3　配方关系没人维护：`chainFactor` 整节缺失

§7 的迁移表列了 `buyImpact/sellImpact`、`LOCAL_SPREAD`、`quirk/daily`、`demandBonus/roleDemand/supplyPenalty`、`worldIndex`、`area`、`stock`、`marketDay`、`askUnit`，**唯独没有 `chainFactor`**（`market/Chain.java:68`）：

```
chainFactor = clamp(本村成本 / 中立成本, 0.6, 2.0)
本村成本按配方递归，每件材料乘 levelFactor（需求 1.35 / 本村出产 0.90 / 用途 1.18 / 菜酒 1.35）
```

这是现役唯一让"本村缺原料 → 用该原料做的成品也贵"的机制。而设计把 `levelFactor` 的三个来源（demandBonus / roleDemand / supplyPenalty）全删了，等于**把 chainFactor 的输入也一并删掉，却没有说它怎么办**。

后果：每个物品一条独立 anchor，配方建立的线性关系（9 铁锭 → 1 铁块、1 木 → 4 木板）不再被价格维持，于是跨物品套利出现。

**这不是理论风险，现役基础价表本身就已经裂开了。** 可验证的检查：

- `config/tradepost/market/values.json` 手工把铁块、金块、煤块钉成精确的 9×：`iron_block: 18.0`（= 9×2.0）、`gold_block: 28.8`（= 9×3.2）、`coal_block: 3.2`。
- 但 `diamond_block`、`netherite_block`、`lapis_block`、`redstone_block` **不在手写表里**，会落到 `tag_values.json` 的 `"#c:storage_blocks": 8.0`，再乘稀有度 → 约 **19.2**；而它的 9 个原料是 24×9 = **216**。**11 倍不对称。**
- 杂货货架（`market/VillageMarket.java:481-509`）的池子是 `catalog.all()` —— 注册表里所有有价的物品，按村坐标哈希抽。**钻石块完全可能被抽进某个村的买页。**

**进游戏一条命令就能验证**：`/tradepost why minecraft:diamond_block`
若返回"标签基价 8 × 稀有度 R3(2.4)"，那么：买 1 块 ≈ 16 颗 → 拆 9 颗钻石 → 卖 9×15 = 135 颗。

一般式更值得写进设计：**分解方向的套利系数 = spread / craftPenalty**。

| 时点 | 计算 | 系数 |
|---|---|---|
| 现役（spread 0.75，craftPenalty 0.65） | 0.75 / 0.65 | **1.154**（+15%） |
| 新案（fee 6% ⇒ 0.94，craftPenalty 0.65） | 0.94 / 0.65 | **1.446**（+45%） |

也就是说：**撤掉 0.75 会让所有"1 块 = 9 件"的可分解物自动多赚 45%**，除非同时处理 craftPenalty 或配方关系。

**修法（两条都要）**：
1. **anchor 沿配方图传播**：成品的 anchor 由原料 anchor 加权合成（或成品的 P 直接由"原料 P 之和 × craftPenalty"算出，再乘成品自身的稀缺因子），这样"原料贵 → 成品也贵"由数据保证，而不是靠一个写死的系数。
2. **可分解物强制对称**：块价 = n × 原料价，不吃 craftPenalty（现役手写表已经在这么做，只是漏了 4 个块）。

## 3. 重要问题（P1）

### P1-1　噪声量纲与目标相反

`m = 0.02 + 0.05×√base` 的单位是**绝对颗数**，不是百分比：

| base | m（颗） | 占 base | 落到显示层 |
|---|---|---|---|
| 0.03 | ±0.029 | **±96%** | 一份 38 件 = 1 颗的货，件数会在 18~60 之间乱跳 |
| 2 | ±0.091 | ±4.5% | 可感知 |
| 24 | ±0.265 | ±1.1% | 几乎不可感知 |
| 180 | ±0.691 | **±0.38%** | 连一颗整币都不一定动 |

设计 §5.5 把这张表解读为"小麦会动了、下界合金稳了"，方向本身是**有意选择**，但它同时意味着：便宜货成为波动最大的一档，而 §1 痛点 B 抱怨的正是"便宜货不动"。两条放在一起，等于把痛点 B 反转成了新问题。

**修法**：
1. 噪声写在对数空间（`ln P = ln base + ln anchor + ε`，ε 幅度固定）→ 百分比一致、乘性、天然不会为负；
2. 便宜货的"可感知波动"不要靠单价，靠**报价件数**（现役 `Lot.of` 已经在做这件事：0.0255/件 → 38 件 = 1 颗，单价变 20% 就是 31 件 = 1 颗，玩家能看见）；
3. 两个一起用：单价用对数噪声，展示层用"件数取整"的抖动。

### P1-2　当日价格固定 ⇒ 日内零价格摩擦

§5.4 明确"当天价格固定；成交只改账本与库存，不改当天 P"。好处是杜绝瞬时套利，代价是：

- 玩家一天内可以按同一个价**无限吃**某个村的货，价格只受库存 cap 限制（而 cap 又是 `512/base`，便宜货 4096 件）；
- 现役"买多了会变贵"的反馈（`buyImpact`）彻底消失，玩家会把它读成"定价坏了"；
- 大额扫货的唯一后果是次日 +5%（pMax），对"买来自己用"的玩家等于免费。

**修法（择一）**：
- **日内阶梯**：同一件货当天每成交 N 件，价上浮一个固定档（`+2%/档`），日结清零 —— 只影响当天，不影响隔日不变量；
- **日内滑点**：按"`当日已成交件数 / cap`"做一个 0.9~1.1 的小乘区（幅度小于 fee，所以不构成套利）。

### P1-3　不变量只覆盖单日，挡不住持有

fee 6% ≥ pMax 5% 只能证明"今天买、明天卖"亏 1%。但 anchor 是慢变量、账本还打算做成可视化面板（§5.1），玩家看到某村连续缺铁，今天买入、持有 7 天，按 pMax 全速上涨 = +40.7%，扣 fee 净 **+33%**，全程零风险。

这不是 bug，是"投资玩法"——但 §6 的标题写着"防套利铁律"、"任何低价买次日卖都是套利"，**说过头了**。建议改写为：

> 不变量保证：**原地买卖**与**隔日买卖**不可套利。跨日持有收益是设计允许的"投资"，其上界由 pMax、anchor 上限与库存 cap 共同决定。

并把 `E[持有 N 天收益] ≤ fee` 写成标定目标（或者接受它，但要求吃库存风险：买光后价格未必涨、cap 卡着买不满）。

### P1-4　`pressure` 在薄市场恒饱和

`pressure = netFlow / (volume + floor)`，`floor ≈ 1`。单人服里绝大多数物品的日流通量是 0~5 件：

- 卖 10 件、买 0 件：pressure = −10/11 = **−0.91**，κ×pressure = −0.27 → 被夹到 −0.05；
- 也就是说**任何一笔交易都会把 pressure 打满夹子**，anchor 按最大速度移动，与"这笔交易多大"无关。

这与 §5.2 的核心卖点"按流通量归一，一笔交易能撬动多少价取决于这件货平时流多少"直接矛盾 —— 在薄市场里没有"平时"，floor=1 让分母失去意义。

**修法**：floor 与容量挂钩，或改用软饱和：

```
pressure = tanh( netFlow / (κ0 × cap) )        // cap = 该村该货库存上限
```

`κ0 = 0.25` 时：净流 25% cap → 0.24，100% cap → 0.76，300% cap → 0.995。这样"1 件"在 cap 4096 的小麦上几乎无影响，在 cap 16 的下界合金上有明显影响 —— 稀缺品敏感，正是设计想要的。

### P1-5　性能：必须给"日结快照"留位置

设计说"服务端主线程零聚合，成交只记账"，这解决的是**写**，没解决**读**。现役开页 2.4 s 的实测（`收购定价慢 2481 ms：farmersdelight:kelp_roll_slice`、`开页 3028 ms＝市场 539 ＋收购 2479 ＋回收 2 ＋货架 2 ＋风气 4`）是**生成货架**的成本，不是定价公式的成本。新模型如果每次开页现算"三层 anchor × noise × 每件货"，只会更慢。

**修法**：每日结算时把 P 落成一张表（`村 × 物品 → 整数报价 + 件数`），开页只查表；noise 当天固定，正好一起烘进去。表可以懒生成（第一次访问某村时算全村），并随日结失效。

## 4. 次要问题（P2）

1. **冷启动没有结构性价差**。现役靠 `industries.json` 的 supply/demand + `levelFactor` 制造"产铁村便宜、缺铁村贵"；新案 anchor 全部从 1 起、账本从 0 起，**第一天所有村同价**，跑商玩法要等玩家自己把流量喂进去才出现。建议：anchor 的初值用 `industries.json` 折算（产铁村 0.90、缺铁村 1.12），账本只负责后续修正。
2. **三层 λ 没有分级**。§5.6 只给了权重 0.15/0.35/0.5。三层要产生"跑商"而不是"三个一样的数"，回归速度必须分开：`λ_global 0.01 < λ_area 0.03 < λ_local 0.08`，否则三层同相、权重只是把同一个数放大。
3. **库存只限量之后，UI 必须解释"为什么不能卖"**。现役卖页 `avail = min(structural, (cap − 库存)/lot)`，玩家看到"价格没变但卖不出去"。设计里没有对应交互。现役已有"售罄行画红叉"的机制（`MarketMerchant.markSoldOut`）可以复用，但文案要写清"本村今天还能收 N 件"。
4. **存档迁移没有方案**。现役存档是 `data/tradepost_market.dat`（`v = 4`，含 `village_xp / wallets / stock / world / area / gear / seen_price`）。新案要新增 `ledger S/D` 与 `anchor`，需要 v5 + 从 `world/area/stock` 反推初始 anchor，否则老存档全部从 1 起跳。
5. **多玩家与"鲸鱼"**。anchor 是每村共享的标量，一个玩家的买卖会改变所有人的价格。这是设计意图，但需要一条明确的态度：**允许操纵，但操纵的成本 ≥ 收益**（pMax 上限 + 库存 cap 已经在做这件事）。文档应写明，避免以后被当成 bug。
6. **"库存与价格无关"只对了一半**。`Stock.cap = 512/base` ⇒ 便宜货能买 4096 件、贵货只能买 16 件。"能买多少"仍由价格决定，所以"库存退出定价"准确说法是"库存退出**单价**"。

## 5. 建议的落地顺序

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **phase 0** | 修 P0-1（anchor 数学）、P0-2（marketDay 对称化）、P0-3（配方关系 + 块价对称） | 单测：`a*` 稳态可达且不撞夹；集市日同日买卖净亏；买 1 块拆 9 件卖净亏 |
| phase 1 | 只记账：S/D 三层账本 + 调试命令 `/tradepost ledger` | 玩 1~2 周，能导出"某村某货 7 天 S/D/price"曲线并解释每次价格变化 |
| phase 2 | 单村层 anchor + 牌价 + fee=6%，删 `buyImpact/sellImpact`；**保留 `min(卖价, 要价×0.75)` 作兜底开关** | 回归测试：买光→再卖亏 6%；开页 < 200 ms；7 天持有收益有界 |
| phase 3 | 区域层 anchor（λ=0.03），跨村价差 | A→B 跑商毛利 8~20%，原地倒卖仍亏 |
| phase 4 | 全球层 anchor（λ=0.01） | 长周期趋势可解释，不产生通胀 |
| phase 5 | 噪声（对数空间）+ marketDay 并入 anchor | 价格波动幅度与 base 无关（百分比一致） |

**phase 2 的兜底开关值得特别强调**：0.75 留着、正常不触发、出问题立刻接管。这层保险几乎零成本，专防"重构后重开刷钱"这类回归 —— 现役就是这么被刷过一次的。

## 6. 参数建议（替换 §8 的表）

| 参数 | 建议值 | 说明 |
|---|---|---|
| fee | 6%（首版可 8%） | 必须 ≥ 单日最大涨幅；且必须 ≥ 任何确定性日期乘区的幅度 |
| η（滞后） | 0.05 | 决定"多快到位"，半衰期 ≈ 13.5 天 |
| β（弹性） | 1.0 | 决定"供需能把价格推多远"；单日最大涨幅 = η×β = 5% |
| anchor 区间 | [0.5, 3.0] | 比 [0.2, 5.0] 温和；5 倍价差对玩家太剧烈 |
| pressure | `tanh(netFlow / (0.25 × cap))` | 取代 `netFlow/(volume+1)`，解决薄市场饱和 |
| α（账本 EMA） | 0.2 | 保留（半衰期 3 天），与 §5.1 一致 |
| 三层 λ | 0.01 / 0.03 / 0.08 | 全球慢、本村快；权重 0.15/0.35/0.5 保留 |
| 噪声 | `σ = 2.5%`（对数空间） | 与 base 无关；展示层靠件数取整体现 |
| marketDaySell | **1.10（= 买侧）** | 或只作用于买侧 |

## 7. 三个可量化的验证实验（phase 0 结束后跑）

1. **集市日套利**：模拟"非集市日买 1 件 → 第 6 天集市日卖 1 件"，收益必须 < −fee。
2. **块↔件套利**：对每个"1 块 = 9 件"的物品，验证 `卖(9 件) ≤ 买(1 块) × (1−fee)`。用 `/tradepost why` 逐个核对基础价（`diamond_block` 是当前最可疑的一个）。
3. **持有套利**：模拟"连续缺货村，第 1 天买、第 7 天卖"，收益上界 = `(1+ηβ)^7 × (1−fee) − 1`，必须写进文档作为已知特性。
